## Prompt 1 【SDD 阶段】数据建模与 API 契约
**原文：**

```
【SDD 阶段】现在只写文档，不写业务代码。请在 docs/ 下产出三份 markdown：

1. docs/PRD.md
   - 用户故事 + 每条的验收标准（Given/When/Then）
   - 把作业里所有「禁止」写成可测试的验收标准

2. docs/ER.md（用 mermaid erDiagram）
   至少包含这些实体，字段你来设计，每个字段写类型和含义：
   - discussion（讨论：话题、状态、专家人数、创建时间）
   - participant（主持人/专家：姓名、职业、title、立场、颜色、角色 host/expert）
   - utterance（Transcript 里的公开发言）
   - event（事件流：区分 public 和 internal，internal 如举手/抢话意图不进 Transcript）
   - insight（共识/分歧条目：类型、内容、支持者、状态、更新时间）
   - agent_state（专家小窗：idle / preparing / speaking、当前关注点、公开思考摘要）
   再画一张讨论状态机图（mermaid stateDiagram）：draft → lineup_ready → running → summarizing → done，以及允许的失败/中止分支。

3. docs/API.md
   每个接口写：方法、路径、请求体、响应体、错误码（统一错误格式 {code, message}）。至少包括：
   - POST /api/discussions 创建讨论并生成嘉宾阵容
   - POST /api/discussions/{id}/lineup/regenerate 重新生成阵容
   - POST /api/discussions/{id}/start 确认阵容并开始
   - GET  /api/discussions 列表（首页）
   - GET  /api/discussions/{id} 详情（含已有 transcript、insights、agent_states，用于中途加入观看）
   - GET  /api/discussions/{id}/stream SSE，写清每种事件的 event 名和 data 结构，支持 Last-Event-ID 断线补发
   SSE 只推 public 事件和 agent_state 更新，internal 事件绝不下发。

写完停下，列出你做的关键设计取舍（3–5 条），等我审。
```

**复盘：** 目的是先把实体、事件类型和接口契约定死，让后面的前端、测试和实现都对着同一份文档写。审稿时我追问「错误码有没有考虑 404、409、422、502」，AI 逐个接口对照后找出三处缺口：SSE 的 `after` 参数没有校验；阵容生成期间的并发请求没有定义（补了 409 `LINEUP_GENERATING`，后端给每场讨论加锁）；超时和其他上游失败没有区分（决定都归入 502，原因写进内部日志）。

## Prompt 2 【SDD 阶段】数据层落地
**原文：**

```
【SDD 阶段续】按 docs/ER.md 和 docs/API.md 落地数据层，不写业务逻辑：

1. backend/db/schema.sql：SQLite 建表脚本，含外键和索引（event 按 discussion_id + id 建索引，用于 SSE 补发）
2. backend/db/seed.py：至少 5 条高质量样例数据，每条都是完整的「话题 + 主持人 + 4 位专家阵容」，话题要多样（科技、教育、商业、社会、医疗各一），专家立场要真的有冲突。其中 2 条带已完成的 transcript、insights 和总结，方便首页一打开就有东西看。
3. backend/app/schemas.py：API.md 里所有请求/响应的 Pydantic 模型，加上必要校验（话题长度 5–200、专家人数 2–6 默认 4、颜色是合法 hex）
4. backend/app/db.py：SQLite 连接（SQLAlchemy），启动时自动建表
5. 写一个最小的 pytest：建表 → 跑 seed → 断言 5 条讨论存在、每条有 1 个 host 和 ≥2 个 expert

只做这些。跑通 pytest 后把输出贴给我，然后停下。
```

**复盘：** 目的是让 ER 图变成真实的表和约束，样例数据先通过 Pydantic 模型再写入，顺便验证 schemas.py。AI 第一版给样例的共识条目手写了「在第几条发言后生成」，有的条目引用了之后才出现的发言，代码还会悄悄丢掉不存在的引用；自查时改成按引用的最后一条发言推算时间，并去掉静默过滤。测试一次全绿后，又故意改坏数据确认断言会失败。

```
【DDD 阶段 · UI 改版】现在的界面像后台管理页，不像演播厅。这一轮只改前端视觉和布局，不动数据结构和接口。

一、先修两处违规（最优先）
1. 专家小窗的「公开思考摘要」不能出现任何发言意图（想补充、想反驳、想接话），只写观点本身。从数据源头改，不要只在前端过滤。

二、定 token（先输出 token 表给我看，确认后再改组件）
```

## Prompt 5 【TDD 阶段】先写测试和 FakeLLM
**原文：**

```
【TDD 阶段】现在写后端核心逻辑，但先只写测试，不写实现。测试必须能在 LLM_MODE=mock 下跑（用一个可控的 FakeLLM，按脚本返回固定内容）。

请在 backend/tests/ 写以下测试，每个测试名要能读出业务含义：

嘉宾生成
- 生成的阵容人数等于请求人数，且恰好 1 个主持人
- 大模型返回非法 JSON 时重试，重试仍失败返回 502 错误码
- 每位嘉宾颜色互不相同

状态机
- draft 不能直接 start（必须先有阵容）
- done 之后再 start 返回 409
- 同一讨论重复 start 不会起两个后台任务

发言调度
- 主持人第一个发言（开场）
- 每轮由各专家给出发言意图（raise_hand / interrupt / supplement / rebut + 紧迫度），调度器选紧迫度最高者；同分时最久没发言的优先
- 同一专家不能连续发言超过 2 次
- 每 N 轮主持人插入一次追问或串联
- 每条发言不超过 2 句（超出时截断或重生成）
- 发言意图只写入 internal event，不写入 utterance

共识与分歧
- 每条发言后都会触发一次提炼，insight 增量更新（新增/合并/状态变化），不是等结束才生成
- 提炼结果 JSON 解析失败时保留上一版 insights，不清空

隔离
- 同时跑两个讨论，A 的 transcript、event、insight 里不出现 B 的任何数据
- SSE 订阅 A 只收到 A 的事件，且收不到 internal 事件

总结
- 结束时生成总结，存库的是自然语言文本，API 返回里不含原始 JSON 结构

只写测试和 FakeLLM，此时测试应该全部失败。跑一遍把失败输出贴给我，停下。
```

**复盘：** 目的是让测试先替实现定下接口：`pick_speaker` 是纯函数，FakeLLM 按用途返回脚本内容，并用结构化的 hints 拿到人数和 id，不去解析提示词。这份需求和 PRD 有三处不一致（连续发言上限、提炼频率、选人规则），AI 先列出来再按提示词写；为了让 38 个测试各自以「模块不存在」失败、而不是整个文件收集报错，被测模块改在测试函数内部导入，并按失败原因分组确认没有一个是测试自己写错。

## Prompt 6 【TDD 阶段】实现业务逻辑让测试转绿
**原文：**

```
【TDD 阶段续】实现业务逻辑，让 backend/tests 全部通过。约束：

- 每个讨论一个独立的 asyncio 后台任务（orchestrator），所有状态都按 discussion_id 隔离，不用全局变量存讨论上下文
- 每个专家调用大模型时，只给它：话题、自己的人设、最近 K 条公开发言、当前 insights。不给其他专家的内部意图（这样各 AI 上下文是割裂的，讨论才有碰撞）
- 发言意图、调度决策写 internal event；发言写 utterance + public event；agent_state 变化写 public event
- 大模型调用统一走 backend/app/llm.py，有 mock 和 deepseek 两种模式，由环境变量 LLM_MODE 切换；DEEPSEEK_API_KEY 只从环境变量读
- 所有 Prompt 模板放 backend/app/prompts/ 下单独文件，不要散落在代码里
- 结构化输出（意图、insights）要求模型返回 JSON 并用 Pydantic 校验，失败重试 1 次

一次只实现一个模块，顺序：llm.py → 嘉宾生成 → 状态机 → 调度器 → 共识提炼 → 总结 → SSE 接口。每完成一个模块跑一次相关测试，报告通过情况再继续下一个。

不要为了让测试通过去改测试。如果你认为某个测试本身写错了，先停下来告诉我理由。
```

**复盘：** 「每位专家只看自己的上下文」要求意图逐位专家调用，而测试按一次调用返回全部意图来写；AI 没有改测试，而是让 hints 带上全部 id 和本人 id、编排器只取本人那条，测试的强制约束依然成立。查 DeepSeek 文档时发现 `deepseek-chat` 已在 2026-07-24 停用，改用 `deepseek-v4-flash` 并关闭思考模式，从源头不产生隐藏思维链；测试只覆盖到生成器，所以又在真实端口上验证了 SSE 的断线续传。

## Prompt 7 【E2E 阶段】接真实后端，端到端测试与质量闭环
**原文：**

```
【E2E 阶段】把前端的 mock 换成真实后端（仍用 LLM_MODE=mock），然后补端到端测试：

1. 前端改用真实 API 和 SSE（EventSource），断线自动重连并带 Last-Event-ID 补发
2. 中途进入一个正在进行的讨论：先拉详情接口拿历史，再接 SSE，不重复、不丢消息

   - 同时打开两个讨论的演播厅，互相不串内容
   - 页面上任何地方都找不到「举手」「raise_hand」「{」开头的 JSON 原文

```

**复盘：** 断线重连测试连失败三轮，每轮都先查原因：Chrome 的离线模拟不会切断已建立的 SSE 连接，于是改由服务端定时断开（`SSE_MAX_STREAM_S`）让重连真实发生；`request.headers()` 取不到网络层的 `Last-Event-ID`，要用 `allHeaders()`；还发现「进行中无空洞」的检查被 `if` 悄悄跳过，改成必过断言，并用「故意丢事件」的变异确认检查真的会失败。E2E 截图还暴露了一个后端漏洞：更新操作能让分歧只剩一边，补了校验和回归测试。

## Prompt 8 【E2E 阶段】真实模型评测与 Prompt 调优
**原文：**

```
现在切到 LLM_MODE=deepseek 跑一场真实讨论，话题用种子数据里的第 1 条。跑完帮我做一次质量检查，逐条打分（好/一般/差）并给证据：
1. 专家发言是不是有真的交锋（点名反驳、补充），还是各说各话
2. 每条是不是控制在 1–2 句
3. 主持人有没有在合适时机追问和串联
4. 共识/分歧是不是随发言实时变化，内容有没有和 transcript 对不上的「幻觉」
5. 专家小窗的「公开思考摘要」是不是在泄露推理过程
6. 总结是否是自然语言

只针对「差」的项修改 backend/app/prompts/ 里的模板，每次只改一处，改完再跑一场对比。告诉我改了什么、前后效果差别。
```

**复盘：** 先查余额、报预算（上限 ¥2），4 场实际花了 ¥0.22。第一场真实运行就崩溃：模型写出「2 句但 133 字」的发言，超过数据库上限，这是 mock 永远测不到的，补了 `fit_utterance` 和用真实输出做的回归测试。打分只有第 4 项「差」（共识的站队有幻觉，还被总结照抄）；第一次改模板（站队需本人发言为证）修住了幻觉，却让模型改填姓名、25 个操作被拒、实时性停滞，第二次改模板（id 不能填姓名）才两头都好，说明 Prompt 修改要看副作用，不能只看目标指标。
