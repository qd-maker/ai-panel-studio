# 开发过程与工作流说明

## 开发流程

开发工具是 Claude Code，模型用 Claude 系列；应用运行时调用的大模型是 DeepSeek。作业建议的组合是「Claude Code 结合 DeepSeek V4 Pro」，这里按实际使用的工具如实说明。

项目按四个范式推进。每个阶段由我写一段提示词，AI 完成后停下等我审核，通过再提交；提示词原文和复盘记在 [prompts.md](prompts.md)，提交历史按 `docs → schema → ui-components → test → feat` 分层。

| 阶段 | AI 的产出 | 我把关的东西 |
| --- | --- | --- |
| SDD | PRD、ER 图、API 契约、建表脚本、Pydantic 模型 | 错误码是否齐全、禁止项能否写成测试 |
| DDD | 组件、三档布局，逐页截图确认 | 是否像演播厅、是否违反禁止项 |
| TDD | 先写 38 个失败的测试和 FakeLLM，再逐个模块实现 | 测试名能否读出业务含义；不许为通过而改测试 |
| E2E | 前端接真实接口、Playwright 测试、docker-compose | 失败先分析原因再修 |

管理 AI 上下文靠三件事：**文档是唯一事实来源**，每个阶段的提示词都要求「按 docs/ER.md 和 docs/API.md」实现，规则变了先改文档；**测试约束 AI 的输出**，让测试替实现定下接口；**小步推进**，一次只实现一个模块并跑测试汇报，偏差的影响范围小。

## 与 AI 协同中遇到的典型问题

**问题一：AI 验收只查字面关键词，漏掉了真正的违规。** 专家小窗的模拟数据里出现了「想接着『补充许安的说法』说两句」，AI 的验收脚本只查「举手」「抢话」几个字，报告通过。我要求从数据源头修：后端 `AgentState` 的观点字段加上「不含发言意图」的校验并补测试，之后三场真实讨论共 144 条思考摘要都不含发言意图。把要求落到 schema 校验上，比让 AI「记得遵守」可靠。

**问题二：测试全绿，但检查本身没在起作用。** 断线重连测试连败三轮，每轮先查原因：Chrome 的离线模拟不会切断已建立的 SSE 连接，改由服务端定时断开；断言读不到 `Last-Event-ID`，AI 先猜是 StrictMode，打印请求后才发现是要用 `allHeaders()`；「进行中无空洞」的检查写在 `if` 里被悄悄跳过。修好后我又要求做变异检查：临时让前端丢掉三分之一的事件，确认相关测试都会失败。测试通过不等于测试有效。

**问题三：只盯目标指标改 Prompt，会带来副作用。** 真实模型评测时，一条只有一人说过的观点被标成四人认同，还被总结照抄。第一次改 Prompt 要求站队需本人发言为证，幻觉没了，模型却开始把姓名填进 id 字段，25 个操作被拒、共识区停滞；第二次规定「id 只能填 32 位 id」才两头都好。同一轮还发现 mock 测不到的 bug：模型写出「2 句、133 字」的发言，超过数据库上限导致崩溃。每次只改一处、对照多个指标看，才分得清改进和副作用。

## 对「工程化 AI 开发」的理解

AI 能很快写出大量代码，工程化要解决的是让这些代码可控、可验证、可追溯：

1. **契约先行**：先写 PRD、ER、API，AI 的每一步都有可核对的标准。
2. **用机器检查约束 AI**：数据库约束、Pydantic 校验、单元测试、E2E、变异检查层层把关，能写成检查的要求就不靠 AI 自觉。
3. **小步提交、过程留痕**：问题能定位到引入它的那一步，每个决定都讲得清来由。
4. **在真实环境里验证**：mock 让测试快而稳，但上线前必须用真实模型跑一遍，并先报预算、控制成本。

人负责定义问题、设定约束、审核结果、在 AI 判断出错时纠偏；AI 负责在约束内把事情快速做完。
